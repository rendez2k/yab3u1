# Alternative workbench

Mode: Operate. Separate test version; no replacement of the established review or production deployment.

## Options evaluated
- Linear wizard: strongest first-run instruction, but frustrates repeated palette/layout edits and hides the model.
- Dense slicer-style dashboard: fast for experts but recreates the current competing-control problem.
- Model-centred workbench: selected. Persistent canvas, four task panels, contextual controls and one output position.
- Card-based home dashboard: useful for a launcher, poor for the actual editing task.
- Full-screen canvas with floating tools: attractive but poor discoverability for the existing settings breadth.
- Document-style progressive form: accessible and simple, but retains excessive vertical movement.
- Separate task apps: modular but worsens project handoff and feature discovery.

## Direction contract
THESIS: One project and one visible model, with a focused inspector for the task at hand.
OWN-WORLD: Warm light inspector surfaces, charcoal model stage, restrained orange actions, crisp rectangular controls and existing YAB3D mark. A working studio rather than a settings document.
STORY: Open a model; choose the destination; decide colours; arrange parts; review and export. Tasks remain freely revisitable.
FIRST VIEWPORT: Compact top project bar, narrow labelled task navigation, generous central stage, right inspector and stable bottom action/status strip. Empty state is an invitation to open a model with a working generated sample.
FORM: Model-centred workbench, third evaluated workflow. User delegated direction selection and requested completion before presentation.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Build uses code-first implementation of real controls and actual model rendering. No generated decorative imagery or invented performance claims. This is a task-specific choice under the user's delegation, not a stored global preference.

## Decision evidence
Concept seed ran successfully with key `86aa858c`, mode operate, assigned candidate 6. The progressive form assignment conflicts with the owner's repeated complaint about long scrolling pages. Under the explicit instruction to evaluate options and build the best version, candidate 3 was selected instead. No user-facing approval gate was added.

The six challengers were evaluated: the variable-font specimen contributes immediate visual feedback; the design annual contributes restrained metadata; the botanical folio contributes stable comparison framing. The streaming-title wall, timetable slide rack and zoo guide map sacrifice control density or predictability in this task. None supplants the model-centred workspace.

The interface uses self-hosted IBM Plex Sans for headings and the platform UI font for controls. Its built-in four-colour support arch is a synthetic working model. The existing YAB3D logo is reused unchanged. No decorative raster was generated.

## Boundaries
Both colour engines keep their own live experiment in memory. First entry to another mode carries the original source, plate, destination, quantities, copies, spacing and PETG reservation; revisiting preserves that mode's own edits. This is stated in Help. Nothing persists model bytes after closing the tab. The legacy Chrome ZIP continues to point to the existing review app, explicitly labelled in Tools; the workbench itself supports the original-file handoff receiver.
